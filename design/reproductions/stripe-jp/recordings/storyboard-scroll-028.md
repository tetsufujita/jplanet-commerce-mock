# Stripe JP scroll storyboard — frames 028–053

スクロール速度が速い（約 357px/frame）ため、scroll-triggered な entrance はフレーム間で完了してしまうものが多い。
この範囲で確実に観測できたのは **(a) 連続再生されるインライン動画 / canvas アニメ**、**(b) carousel の状態表示**、**(c) ダッシュボード mock の段階表示** の 3 系統。
全 section は viewport 進入時点でほぼ不透明・最終位置にあり、Stripe 特有の「entrance は控えめ、メディアが常時動く」設計が裏付けられた。

## section 出現パターンの総括

- **entrance アニメ**: この範囲の全 section が viewport 進入時に opacity 1・最終位置で観測された。fade/slide があるとしても ≤333ms か、トリガーが viewport 進入よりかなり手前。再現時は「entrance は無し or ごく短い fade」で十分。
- **動きの主役は常時再生メディア**: Hertz 交差点動画（#6）、Runway 水流動画（#11）、パーティクルバースト（#4）、紫 wave canvas（#20）、サポート section グラデ動画（#2）。
- **構造化 UI の演出**: Zenflow ダッシュボードの widget build-in（#14）と mindbody ロゴ下線 progress（#17）が数少ない「UI そのものが動く」箇所。

## 不確実な点

1. **統計 counter（#3, #20）**: 「135 +」「$1.9兆」「5億 +」等の count-up アニメは 3fps + 高速スクロールでは検出不能。低速スクロール or 静止状態での再録画 or DOM 実測（NumberFlow 系か）が必要。
2. **パーティクルバースト（#4）**: scroll-scrub（スクロール量に連動）か autoplay 動画かを判別できず。逆スクロールで巻き戻るかの確認が必要。
3. **構成図（#19）**: ノード出現の stagger・接続線の draw/flow アニメの有無が未確認。
4. **code editor（#21）**: typing アニメ・terminal 出力の逐次表示の有無が未確認（051/052 でほぼ同一に見える）。
5. **Zenflow ダッシュボード（#14）**: 045 上端で内容が変化して見えるが、クロップの問題か画面 crossfade（複数 dashboard 画面の自動切替）かを判別できず。
6. **mindbody 下線（#17）**: progress bar の周期（自動切替間隔）は単フレームでは測定不能。静止録画で要計測。
7. 033–036 のフレームは出力解像度が低く（縮小レンダリング）、微細な opacity 差は読み取れていない可能性がある。
